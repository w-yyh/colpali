## Slide 1｜章节页

标题：02 轻量级前端复原与“复原-检索”解耦分析

副标题：从图像质量修复到 ColPali 检索收益的边界验证

署名：王昱皓

讲稿：

本部分关注退化文档进入视觉语言检索模型之前的前端复原问题。我们的目标不是单纯让图像看起来更清晰，而是验证复原操作是否真正改善 ColPali/ColQwen2 的 Patch 嵌入质量和最终检索排序。因此，本部分会围绕“退化图像、复原图像、检索指标”三者之间的关系展开。

## Slide 2｜研究问题：视觉复原不必然等价于检索提升

页面要点：

- 真实文档退化包括噪声、模糊、JPEG 压缩、低分辨率、几何倾斜与色彩偏移。
- 前端复原可以改善可视质量，但也可能改变字符边缘、版面结构和局部纹理。
- ColPali 的 Late Interaction 依赖 query token 与 document patch 的局部匹配。
- 因此需要区分两类收益：图像视觉质量收益与检索排序收益。

讲稿：

在传统图像处理任务中，复原效果通常通过图像是否更清晰来判断。但在视觉文档检索中，模型真正关心的是文档语义和版面结构是否更容易被正确匹配。一个去噪或去模糊算法即使提升了主观视觉质量，也可能平滑掉字符细节，或者引入伪影，导致 Patch 嵌入分布发生新的偏移。因此，本部分的核心问题是：前端复原是否能在检索指标上带来稳定收益，以及这种收益在哪些退化类型上成立。

## Slide 3｜方法设计：轻量级复原管线

页面要点：

- 复用仓库中的 `robust/restoration/` 模块。
- 当前已支持三类基础方法：
  - `nlmeans`：非局部均值去噪，面向噪声型退化。
  - `gaussian`：高斯平滑，作为快速低成本基线。
  - `wiener`：Wiener 频域滤波，面向模糊或压缩失真。
- 后续可扩展 DnCNN/FFDNet、轻量 ESRGAN/BSRGAN、倾斜校正。

讲稿：

当前仓库已经提供了一个可组合的复原管线，入口是 `RestorationPipeline`。第一阶段先采用轻量、可复现、离线运行成本低的方法建立基线，包括 NLMeans、高斯平滑和 Wiener 滤波。这些方法不依赖重新训练 ColQwen2，可以直接插入到 `process_images()` 之前，形成 degraded 到 restored 的预处理链路。后续如果需要提升复原能力，再扩展到 DnCNN、FFDNet 或轻量超分模型。

## Slide 4｜实验流程：clean / degraded / restored 三组对照

页面要点：

```text
clean pages
   -> ColQwen2 -> clean baseline

degraded pages
   -> ColQwen2 -> degradation baseline

degraded pages
   -> restoration pipeline
   -> ColQwen2 -> restoration result
```

建议命令：

```bash
python experiments/run_local_hr_benchmark.py --mode clean --model ./colqwen2-v1.0 --local-files-only
python experiments/run_local_hr_benchmark.py --mode degraded --variant PD_MB_GN_JC_LR_CS --model ./colqwen2-v1.0 --local-files-only
python experiments/run_restoration_analysis.py --variant PD_MB_GN_JC_LR_CS --rest nlmeans gaussian wiener
```

讲稿：

实验上需要固定同一批页面、同一批 query 和同一个 ColQwen2 模型，只改变图像输入条件。第一组是 clean baseline，用来表示理想文档图像下的检索上限；第二组是 degraded baseline，用来刻画复合退化带来的性能损失；第三组是 restored result，用来衡量前端复原是否真正把检索性能拉回。最终报告不只看单个数值，而是比较 nDCG@5、Recall@5 和 MRR 三个指标。

## Slide 5｜最终实验结果：轻量复原带来有限但可测的检索收益

说明：以下数字来自 `experiments/run_restoration_analysis.py` 在服务器新建 conda 环境 `wangyuhao-colpali` 中的独立复原实验。固定设置为 `PD_MB_GN_JC_LR_CS` 复合退化、111 页文档图像、174 个单文档 query、ColQwen2 标准 MaxSim。

页面表格：

| 输入条件 | nDCG@5 | Recall@5 | MRR | 相对 degraded nDCG@5 |
|---|---:|---:|---:|---:|
| clean baseline | 0.5717 | 0.5829 | 0.6516 | +0.1144 |
| degraded `PD_MB_GN_JC_LR_CS` | 0.4574 | 0.4090 | 0.6251 | 0.0000 |
| gaussian restored | 0.4592 | 0.4072 | 0.6354 | +0.0018 |
| nlmeans restored | 0.4645 | 0.4085 | 0.6821 | +0.0071 |
| wiener restored | 0.4687 | 0.4194 | 0.6490 | +0.0114 |

讲稿：

从最终独立实验可以看到，复合退化使 nDCG@5 从 clean 的 0.5717 降到 0.4574，说明退化确实显著改变了 ColQwen2 的检索排序。三种轻量复原方法都带来了正向但有限的 nDCG@5 增益，其中 Wiener 滤波达到 0.4687，是 nDCG@5 和 Recall@5 上最好的方法；NLMeans 的 nDCG@5 增益略低，但 MRR 达到 0.6821，说明它更容易把部分 query 的首个相关页面提前。整体来看，复原并没有把性能恢复到 clean 水平，clean 与 degraded 之间仍有约 0.1144 的 nDCG@5 缺口。这支持本部分的核心判断：复原效果必须用检索指标验证，不能只凭视觉观感判断。

## Slide 6｜解耦结论：复原、Adapter 与检索目标的关系

页面要点：

- 前端复原负责改善输入图像，但不直接保证 embedding 排序结构恢复。
- Adapter 负责在 embedding 层修正检索分数，但其效果依赖复原输入分布。
- 当前 full-train Adapter 中：
  - nlmeans + Adapter 仍有正向 nDCG@5 增益。
  - gaussian / wiener + Adapter 在部分指标上转为负收益。
- 说明复原方法与模型层增强存在交互，不能简单相加。

讲稿：

何青泽的 Adapter 结果进一步说明，前端复原和模型层增强不是简单叠加关系。一个复原方法在标准 MaxSim 下有效，不代表接入 Adapter 后仍然有效；反过来，Adapter 的训练目标也可能对某些复原分布更敏感。因此王昱皓部分需要明确自己的边界：先独立评估 restored image + standard MaxSim，再讨论 restored image + Adapter 或 robust late interaction 的组合效果。这样才能回答“图像复原本身贡献了多少，模型增强又贡献了多少”。

## Slide 7｜阶段产出：可复现实验入口与 PPT 可用结论

页面要点：

1. 已补齐 `experiments/run_restoration_analysis.py`，支持本地 HR 数据集、复原方法选择、embedding cache 和 JSON 结果保存。
2. 已输出三组对照结果：clean、degraded、restored。
3. 已覆盖 `gaussian`、`nlmeans`、`wiener` 三个复原基线。
4. 已增加复原增益指标：

```text
Delta nDCG@5 = nDCG@5(restored) - nDCG@5(degraded)
```

5. 结果 JSON 保存到 `results/restoration_analysis/`，页面 embedding cache 保存到 `results/restoration_cache/`。
6. 后续可继续补充 Patch embedding drift 或代表性页面可视化。

讲稿：

王昱皓部分目前已经从占位计划推进到可复现实验入口。脚本复用本地 111 页 HR 数据集加载逻辑，对每种复原方法批量处理 degraded 页面，送入 ColQwen2 后计算 nDCG@5、Recall@5 和 MRR，并保存统一 JSON。PPT 可以直接使用 Slide 5 的表格作为核心结果：轻量复原确实带来小幅检索收益，但收益具有方法差异，并且远小于 clean 与 degraded 之间的缺口。因此，本部分最终呈现的重点不是“复原算法让图像更清楚”，而是“复原是否真正改变检索排序，以及改变的边界在哪里”。
